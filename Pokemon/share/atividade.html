Setup

Preparar o projeto e a entrada

Dependência

Este ticket inicia o laboratório e não possui dependências.

Implementação solicitada

  1. Criar um projeto Console chamado PokedexArquivo.
  2. Criar pokemons.json com os cinco nomes apresentados em entrada.
  3. Criar a classe PokemonInput com a propriedade List<string> Nomes.
  4. Configurar o arquivo para ser copiado para a pasta de saída.
<ItemGroup>
  <None Update="pokemons.json">
    <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>
  </None>
</ItemGroup>

Critérios de aceite

  • O projeto compila sem avisos.
  • pokemons.json aparece ao lado do executável.
  • A lista de entrada contém exatamente cinco nomes.

Validação

dotnet new console -n PokedexArquivo
dotnet build .\PokedexArquivo

Referências

  • Arquivos em projetos do SDK do .NET
  • List<T>

Cliente HTTP

Consultar a PokéAPI

Dependência

Concluir LAB-002.

Usar os nomes carregados em LAB-002 para consultar https://pokeapi.co/api/v2/pokemon/{nome}.

Implementação solicitada

  1. Criar um único HttpClient com a URL base da PokéAPI.
  2. Criar PokemonApiResponse para representar ID, nome, altura, peso, imagem e lista de tipos.
  3. Criar os modelos auxiliares necessários para representar sprites e types da resposta.
  4. Usar JsonPropertyName quando o nome recebido em JSON não corresponder ao padrão das propriedades C#.
  5. Consultar cada nome com GetFromJsonAsync e aguardar a resposta.
  6. Reunir as respostas recebidas para a etapa de transformação.

Critérios de aceite

  • É realizada uma requisição para cada nome.
  • A aplicação utiliza um único HttpClient.
  • ID, nome, altura, peso, tipos e imagem são desserializados.
  • As chamadas utilizam await.

Validação

bulbasaur1grass
charizard6fire

Mapeamento

Criar os objetos detalhados

Dependência

Concluir LAB-003.

Transformar cada resposta obtida em LAB-003 no modelo próprio PokemonDetalhado.

Implementação solicitada

  1. Criar o record PokemonDetalhado com ID, nome, altura em metros, peso em quilogramas, lista de tipos e endereço da imagem.
  2. Converter altura de decímetros para metros.
  3. Converter peso de hectogramas para quilogramas.
  4. Extrair os nomes dos tipos com Select.
  5. Adicionar o objeto transformado à coleção final.

Critérios de aceite

  • Pikachu possui 0.4 metro e 6 quilogramas.
  • Bulbasaur contém os tipos grass e poison.
  • A coleção final não expõe a estrutura completa da PokéAPI.

Validação

25 | pikachu   | 0,4 m | 6 kg   | electric
 1 | bulbasaur | 0,7 m | 6,9 kg | grass, poison

  • Enumerable.Select

Fluxo da aplicação

Criar o menu principal

Dependência

Concluir LAB-005.

Organizar as funcionalidades concluídas até LAB-005 em uma aplicação interativa que permanece aberta até o usuário solicitar a saída.

Implementação solicitada

  1. Exibir as opções 1 - Ler arquivo enriquecido, 2 - Enriquecer arquivo e 0 - Sair.
  2. Ler a opção informada pelo usuário.
  3. Manter o menu em repetição após a conclusão de cada operação.
  4. Encerrar a aplicação somente quando a opção 0 for selecionada.
  5. Apresentar uma mensagem clara para opções inválidas e exibir o menu novamente.

Critérios de aceite

  • As três opções são exibidas com descrições compreensíveis.
  • O menu reaparece depois das opções 1 e 2.
  • A opção 0 encerra a repetição.
  • Uma opção inválida não encerra nem trava a aplicação.

Validação

  1. Informar uma opção inválida e confirmar a nova exibição do menu.
  2. Selecionar 1 e confirmar que a aplicação retorna ao menu.
  3. Selecionar 2 e confirmar que a aplicação retorna ao menu.
  4. Selecionar 0 e confirmar o encerramento.

Referências

  • Instruções de iteração em C#

Desafio

Tratar Pokémon inexistente

Dependência

Concluir LAB-008.

Adicionar missingno ao arquivo de entrada após concluir LAB-008.

Implementação solicitada

  • Usar GetAsync para inspecionar o código de status.
  • Registrar o nome não encontrado no terminal.
  • Continuar o processamento dos demais nomes.
  • Não criar um objeto vazio para a resposta 404 Not Found.

Critérios de aceite

  • A mensagem identifica o nome não encontrado.
  • Os demais Pokémon continuam no arquivo final.
  • Somente a resposta 404 recebe esse tratamento.

Validação

Executar com missingno entre dois nomes válidos e confirmar que o arquivo final contém somente os válidos.

Referências

  • HttpClient.GetAsync
  • HttpResponseMessage.StatusCode
